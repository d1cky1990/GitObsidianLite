# 单一公开仓，不切分出私有的开发仓或发布仓

`GitObsidianLite` 是唯一的源码仓：产品代码、设计档案、ADR、issue 与 PR 全在这里，公开。曾考虑三仓模型（私有开发仓 + 公开开发仓 + 干净产品仓），否决。

判据是**切分依据必须客观且不漂移**。「完备程度」主观且随时间变化——今天觉得没写完、明天觉得够好了——拿它分仓会导致反复搬家；「归属」是客观的：一份东西要么是给这个软件的读者看的，要么不是。产品代码与已经解决的决策属于前者（进本仓）；个人操作笔记与凭据属于后者（**不进任何仓库**，见 ADR-0002）。

因此也没有再切出「干净的发布仓」——它是本仓的一个投影，靠 README（面向部署者）+ GitHub Release 表达，**不复制源码**。

## Considered Options

- **三仓（私有开发 + 公开开发 + 干净产品）** —— 否决。公开开发仓与干净产品仓的内容差异只有「有没有开发过程」一条，两者源码重叠，必须养一套同步机制，而**漂移是必然的**。
- **两仓（公开 + 私有账本仓）** —— 否决。私有账本仓本应只装个人笔记与凭据，而这两样的正确归宿是密码管理器与平台环境变量，不是 git。
- **单仓 + `release` 分支** —— 不需要。发布靠 tag + GitHub Release 已经够，分支只会多一个要同步的地方。

## Consequences

- 设计档案（上一轮 wayfinder 的全部产物）进本仓的 `docs/design/`，**但必须先校正**：它停在 2026-08-29，`spec.md` 的「部署步骤」一节至今写着已被推翻的结论（EdgeOne Pages + ICP 备案），而真正在用的平台没有回写。**一份会把人带沟里的文档比没有文档更糟。**
- `AGENTS.md` 与 `docs/agents/` 进本仓：它们是给协作者与 agent 看的，属于公开面。
- 「拿来直接用」的入口由 README + Release 承担，不新建仓库。
