# 项目级工作记忆不承载知识

`.workbuddy/memory/` 是 AI 助手的工作记忆，本项目**不把它当作知识来源**。决策、方案、待办一律回写到它们该在的地方：已定型的决策 → `CONTEXT.md` 与 `docs/adr/`；在飞的决策与待办 → issue tracker；对使用者有用的操作流程 → README 或 `docs/`。记忆里出现的决策视为缺陷，必须回写。

诱因是一次具体的失修。上一轮的决策档案停在 2026-08-29：`spec.md` 的「部署步骤」至今写着 **EdgeOne Pages + 绑指定域名需 ICP 备案**，而实际部署在别处；真正在用的平台只存在于记忆里，从未回写进任何设计档案。**记忆与设计档案互为副本时，两份都会漂移——而记忆里的那份，没有人会去校对。**

这同时也是 matt 套组的设计意图：agent 的知识来源是 `CONTEXT.md`、ADR 与 issue，不是记忆。记忆是这两者都不成熟时的临时拐杖。

## Consequences

- agent 每次开工的读物是 `CONTEXT.md`、`docs/adr/`、`docs/agents/`、README 与 issue tracker——**不读记忆**。
- **记忆里不得出现凭据**。密码住 `server/.dev.vars`（已 ignore）或密码管理器，部署密钥住平台环境变量（见 ADR-0001）。理由不只是「危险」：记忆是每次会话必读的文件，明文密钥在里面等于**每开一次会话就外流一次**。
- 记忆里可以留的只有：跨项目环境坑（且应放用户级记忆，不该按项目重复）、以及指向上面那些位置的指针。
