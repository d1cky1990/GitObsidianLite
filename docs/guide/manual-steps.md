# 要你本人点网页的几步（图文指引）

这份只讲**必须你亲手做、脚本代替不了**的事：注册账号、生成令牌。部署怎么做、失败了怎么读，在 [README 的「部署上线」](../../README.md#部署上线cloudflare-workers)——这里不复述，两处副本必然漂移。

**文字为准，图为辅。** 平台一改版截图就过期，所以每一步先写清「认哪几个字样」，图只是帮你对上号。**图还没有**：下面每处的「图 N」是留给截图的位置与要求，补图时把那一小段换成图片。

- **图摄日期**：待补（补图时把这一行改成拍摄日期）
- **公开仓库**：图里**不得出现账号名 / 组织名 / 仓库名**，令牌值更不能入镜

## 从头到尾的顺序

1. 有 Gitee 账号 + 一个放笔记的仓库 → 生成**私人令牌**（第 1 节）
2. 有 Cloudflare 账号 → 生成**API 令牌**（第 2 节）
3. 新账号才需要的：`workers.dev` 子域（第 3 节）
4. 回 README 跑那条部署命令。终点是**手机打开网址看到笔记**，不是「本机跑起来了」

## 1. Gitee 账号与私人令牌

**要什么**：一个 Gitee 账号，和一个放笔记的仓库；仓库可以是私有仓。

**在哪做**：

- 没有账号 → `gitee.com` 注册，邮箱验证。
- 没有仓库 → **这一步不用手动建**。部署命令带 `--create-repo` 时会替你在自己账号下建私有仓，并放一篇示例笔记（见 README「仓库还没建？」）。
- 生成令牌 → 登录后点**头像 → 设置 → 安全设置 → 私人令牌 → 生成新令牌**。页面上认「私人令牌」「生成新令牌」这几个字样；菜单改版时按这两个词找。

**要点什么**：权限只勾 `projects`。别的不用给。

**填进去的值从哪来**：提交后**只显示一次**，先粘到记事本。它就是 `server/.dev.vars` 里 `GITEE_TOKEN` 的值；同一份文件里还要填 `GITEE_OWNER`（你的 Gitee 用户名）与 `GITEE_REPO`（笔记仓库名，**大小写敏感**）。这份文件怎么弄见 README 的「部署上线」。

**填完怎么验证**：不用自己写请求。部署命令第 3 步会拿这份配置去问 Gitee（四项只读检查，清单见 README 的步骤表）。全过就说明这三项都是对的。

> 截之前：把已有令牌的备注名与值遮掉；头像、用户名不入镜。

> **图 2**｜`docs/guide/images/02-gitee-token-scope.png`
> 该截哪一屏：新建令牌时勾选权限的那一屏，只勾了 `projects`。
> 截之前：确认没有其它勾选项；令牌值此时还没生成，不用担心入镜。

## 2. Cloudflare 账号与 API 令牌

**要什么**：一个 Cloudflare 账号（免费档够用），加一个**用户级** API 令牌。

**在哪做**：

- 没有账号 → `dash.cloudflare.com` 注册、邮箱验证。这一步要能打开这个域名，大陆网络下可能得挂一次梯子。
- 生成令牌 → 登录后点**头像 → My Profile → API Tokens → Create Token**，模板选 **Edit Cloudflare Workers**，一路 `Continue to summary` → `Create Token`。

**要点什么**：模板已经带好了权限，不用自己加。**别用错页面**：`Manage Account` 那一页的是「账号级」令牌，wrangler 用不了它（撞上的样子与出路见 README「已知的坑」第一条）。

**填进去的值从哪来**：创建完**只显示一次**，先粘到记事本。它不进配置文件，而是本机环境变量 `CLOUDFLARE_API_TOKEN`——怎么设（在哪个终端里设、为什么设完要重开）、设完怎么确认，见 README「部署上线」的前提第 2 条。

**填完怎么验证**：部署命令第 2 步会再查一次，没设或设错就点名，并告诉你回哪个页面重新生成。

> **图 3**｜`docs/guide/images/03-cf-api-tokens-page.png`
> 该截哪一屏：My Profile → API Tokens 页面，能看到 `Create Token`。
> 截之前：把已有令牌的名称、账号邮箱遮掉。

> **图 4**｜`docs/guide/images/04-cf-token-template.png`
> 该截哪一屏：模板列表里 `Edit Cloudflare Workers` 那一行（选中状态）。
> 截之前：无需处理，但别让账号名出现在左上角。

> **图 5**｜`docs/guide/images/05-cf-token-created.png`
> 该截哪一屏：令牌创建成功、显示令牌值的那一屏。

## 3. （顺带）`workers.dev` 子域，只有新账号会撞上

新账号第一次部署时，代码会传上去，却拿不到网址——缺的是一个一次性的名字：子域。它会进网址、全球唯一，所以脚本不替你编。

- 想先设好：控制台 **Workers & Pages → 右栏 Your subdomain → Change**，自己起一个。
- 想等它撞上来：部署命令会停下来，让你加一个参数重跑；参数怎么加照它的原话做（命令本身见 README）。

**怎么验证**：部署结束时打出来的网址形如 `https://<worker 名>.<子域>.workers.dev`，浏览器打得开就是有了。

> **图 6**｜`docs/guide/images/06-cf-subdomain.png`
> 该截哪一屏：Workers & Pages 页面右栏 `Your subdomain` 那一段。
> 截之前：把子域名遮掉——它等于你的网址。

## 做完之后

1. 回 [README 的「部署上线」](../../README.md#部署上线cloudflare-workers)，跑那条命令。
2. 它结尾会给你一个网址。**手机打开它**：读一篇、改一篇、点一下勾选框。到了这一步才算「跑起来」——本机跑通只算排错的手段。
3. 手机上照旧要挂着梯子，原因写在 README 的「自行部署须知」里（地址本身的脾气，不是配置问题）。
