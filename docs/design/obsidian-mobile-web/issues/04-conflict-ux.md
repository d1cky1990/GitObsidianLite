## Question

编辑/阅读模式切换 + 冲突保底处理的交互长什么样？目标：冲突时不放弃任何一边的改动。

需要产出粗糙原型来 react 的界面：

- 阅读模式（默认）与编辑模式的切换。
- 切编辑模式时的"double check 远端改动"提示。
- 提交时仍冲突的保底合并界面（保留两边、可手动合并，而非覆盖其一）。

## Asset

- 原型：prototypes/conflict-ux-prototype.html（单文件状态机原型，浏览器打开或预览）

## Answer

冲突交互最终定稿（原型 v5）：

- 编辑/阅读：阅读为默认态，点「编辑」才切编辑。
- 切编辑 double check：发现远端改动则弹 toast「远端已更新，已自动加载最新内容」并自动加载最新，不提供「仍编辑旧版」。
- 提交冲突：整体左右两栏（左=本地完整文本、右=远端完整文本），各自文本内用字符级 diff 高亮差异（本地改动橙、远端改动蓝）；点击高亮弹气泡「采纳/不采纳」（可取消重选）；合并结果 = 公共部分 + 采纳的改动。
- 预览浮窗：底部「预览改动处理」从下向上覆盖 2/3；有未处理差异时「提交合并」禁用 + 提示「处理完所有 diff 才能提交合并」。
- 冲突退路：「另存副本」二选一（保留本地版本、远端存为副本 / 保留远端版本、本地存为副本）。
- 遗留：冲突文本很长时的滚动/对照体验，留待真机验证后再定。
