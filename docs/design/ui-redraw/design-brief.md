## 0. 三十秒版本

现在的界面是**两个整页**：一个目录列表页，一个笔记页，靠地址栏来回切。

要变成**一屏两栏**：左边一条**可折叠的目录树侧栏**（手机上滑出盖在正文上，屏幕够宽时常驻），右边是**正文区**，装“阅读 / 编辑 / 冲突”三种态。搜索、新建、设置三件事都从侧栏出发；搜索结果就地在侧栏里替掉树，设置也是。

顺带补两件从零做的东西：**深浅两套配色**（今天只有一套浅色），和**设置面板**（今天不存在）。

你要交两份东西：一份**能点的原型**，一份**视觉规范**。§8 写了格式和验收。

## 1. 这是个什么应用

### 1.1 它是什么

一个**手机浏览器**里用的笔记阅读器/编辑器。笔记存放在一个 git 仓库里（Gitee 或 GitHub，一份部署只连一家），后端是一个自托管的小服务，手机浏览器通过它按需拉取、编辑、提交——替代手机端 Obsidian + git 同步那种“整库拉一遍”的做法。

三件事决定了它的界面该长什么样：

- **单用户、自托管。** 一个人用，仓库是自己的；没有多用户、没有权限、没有协作。
- **手机低频，电脑高频。** 手机上主要“看一眼、改一句”，电脑上继续用 Obsidian 高频编辑。所以手机端不追求功能齐全，追求**打开就能找到那篇、看完就走**。
- **弱网与随时切走是常态。** 地铁里、切到微信再切回来、页面被杀掉重开。界面必须随时说清“你看到的是真的，还是还不知道”。

### 1.2 这次要改的到底是什么

| | 今天 | 这次 |
|---|---|---|
| 屏幕结构 | 两个整页，地址栏切换 | 一屏两栏，侧栏常驻或滑出 |
| 找一篇笔记 | 一层层点进目录，再看列表 | 在持久的树里直接看到全库结构 |
| 搜索 | 输入框钉在目录页顶部，有词就整页换成结果 | 侧栏顶部常驻；结果**就地替掉树**，正文不动 |
| 新建 | 右下角一个带文字的悬浮按钮 | 侧栏里一个按钮，弹窗显示落点 |
| 文件操作 | 每行右侧常驻「⋯」 | 树行不挂常驻按钮：窄屏长按、宽屏悬停；正文顶栏「⋯」是主入口 |
| 设置 | **不存在**（2026-10-27 随一处下架整份删掉） | 在侧栏里就地换掉树，装三块 |
| 深色 | **从来没做过** | 这次新加，三档 |

**注意**：线上那台部署还停在下架之前那一版，所以你在手机上打开会看到一个**旧的**设置页（装的是“搜正文”开关与容量上限）。**那不是这次要做的设置页**，别照着它改。

### 1.3 这次不动的东西

- 技术底子：不引入前端框架、组件库、CSS 框架。今天是无框架的原生 JS + 一个构建工具，之后也是。
- 正文渲染：标题、双链、标签胶囊、勾选框、Tasks 记号、声明区（YAML）、图片——这套规则一条不动，你只决定**它外面包多大、留多少白**。
- 冲突合并的逐字比对界面（左右两栏）与“预览改动处理”那一层：**不改**，你只决定它在新骨架里怎么落位。

## 2. 词汇（先记这七个词）

界面上一律用这些词。它们替代了一批旧词（“目录页”“笔记页”“当前目录”“面包屑”）——旧词**只在描述“今天是什么样”时出现，界面上不再用**。

| 词 | 指的是 |
|---|---|
| **侧栏** | 装树与搜索的那一块。手机上盖在正文上滑出，够宽时常驻左边。 |
| **树** | 侧栏里按文件夹嵌套的笔记名单，也是文件操作的入口。**只列笔记与文件夹**，图片附件不进树。 |
| **正文区** | 右边显示“打开的那篇”的那块，装阅读、编辑、冲突三种态。 |
| **选中的文件夹** | 树里当前高亮的那个文件夹。**新建笔记落在这里**，没选中就落仓库根。它回答“在哪儿操作”，与正在读哪一篇无关。 |
| **打开的那篇** | 正文区正在显示的那篇。换一篇是**同一屏换内容**，不是换一屏。 |
| **正在编辑的那篇** | 处于编辑态或冲突合并里的那篇。 |
| **空状态** | 没打开笔记时正文区那块：一句提示 + 最近打开过的几篇。 |

为什么这么较真：旧代码里一个状态同时当“当前目录”和“当前文件”用，导致**开着笔记时新建会拼出 `某篇笔记.md/新笔记.md` 这种路径**。三个词不拆开，“新建落在哪”就永远说不准。

## 3. 骨架

### 3.1 宽窄两套形态（断点 900px）

**手机（视口 < 900px）——侧栏滑出，盖在正文上**

- **开**：正文左上角一个「☰」。
- 侧栏从左边滑出，**盖在正文上方**，占屏宽 **3/4**（390px 屏约 **292px**），左边留 **1/4** 露出正文边缘。
- **关**：侧栏自带一个关闭键；另外那露出的 1/4 上盖一层**薄遮罩**，**点它关侧栏**（比去找 ✕ 顺手，点击面积也够）。三条关法（再加“点开一篇自动收”）细节见 F-2。
- **不做从屏幕左缘往右划**：iOS 上那个手势是系统自己的“后退”，抢过来会打架；宽屏上没有“划出来”这回事，手势在两套形态里语义不一致。
- **点开一篇笔记，侧栏自动收起。**

**宽屏（视口 ≥ 900px）——侧栏常驻左边**

- 侧栏固定停在左边，正文永远在右边。
- 侧栏**仍可收起**（左上留「☰」），收起状态在**本机记住**。为的是长表格、宽图片能全宽看。
- 收起/展开是即时切换，不做滑动动画的表演（可以有一个短过渡，但不要让人等）。

**为什么是 900**：取 768 会让平板竖屏变常驻，分掉侧栏后正文不到 500px，读着挤；取 844 会让手机横屏常驻，正文掉到 550 上下，而横屏通常只是个临时姿势。900 让手机竖着、横着，和平板竖屏都走滑出；平板横屏与电脑才常驻。

### 3.2 侧栏里装什么：三选一

侧栏内部只用一个位置，三块内容**互斥**：

1. **树**（默认）
2. **搜索结果**（一有词就就地替掉树）
3. **设置面板**

**换内容不进历史**。手机系统返回键只认“侧栏开没开”——开着就收侧栏，不因为里面换成了设置就多退一层。搜索结果替掉树用的是同一条规则，**用户只需要学一遍**。

设置面板和搜索结果都自带一个「‹ 返回目录」回到树，**不靠返回键回**。

侧栏顶部常驻一排入口（搜索 / 新建 / 设置）：**三件都是按钮、常驻显示、不随目录滚动、也不会被滚动内容遮住**。谁和谁并排、谁占多宽、用文字还是只用图标，**归你**（§7 第二栏）。

### 3.3 正文区装什么：三个态

| 态 | 什么时候 | 手机上 |
|---|---|---|
| **阅读** | 打开一篇，正常看 | 占满屏 |
| **编辑** | 点了「编辑」，或刚新建完 | **占满屏** |
| **冲突** | 保存时发现远端被改过 | **占满屏** |

三种态之间是一条直线，每次退一层：**冲突 → 编辑 → 阅读**。

**地址栏只记“右边是哪篇笔记”。** 侧栏开合、树展开到哪、滚到哪，都不进地址栏——否则开一次压一条历史，退出去要按五六下。

## 4. 屏幕与状态清单（逐条）

这是这份文件最要紧的一节。**每一条都是一个必须画出来的屏或态**，包括那些不常见但一定会出现的。编号在 §9 的验收里逐条对照。

### 4.1 侧栏 · 树

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **T-1** | **树还没到手（首次打开）** | 树的来源是“一次整树请求 + 本机那份全库名单”。**第一次打开要等 4.8~6.3 秒**。这期间侧栏不能是空白——要有一个说得出“在等什么”的加载态，并且**不能长得像“这个库是空的”**。 |
| **T-2** | **树还差一点点（后续打开）** | 之后每次打开是一次版本号请求加本地还原（约 1 秒量级）。这一态往往一闪而过；设计要求是**它不能闪成一次布局跳动**（先有骨架还是先有占位，你定）。 |
| **T-3** | **连不上，树画不出来** | 断网时**本机有名单也画不出来**（名单要靠一次版本号请求才敢用）。必须明说“连不上”，**不许**说成“没有笔记”，也**不许**显示一棵空树。给一个“重试”。 |
| **T-4** | **树就绪** | 只列**能到达笔记的路径**（一个文件夹的子树里至少有一篇笔记，它才出现）——配置目录、附件目录、脚本目录因此自动消失，不需要黑名单。真空文件夹不显示（数据源头就不存空目录，不为它改数据层）。排序：**文件夹在前，名字按拼音序**（不能用接口原序，那是字符编码序，中文会乱）。 |
| **T-5** | **正在读的那篇在树里的位置** | 侧栏**每次出现**（手机上拉开、宽屏重画）都按“打开的那篇”摆好：祖先展开、那一行高亮、滚到它附近。**同一次拉开期间用户手动滚动，不被抢回去**。 |
| **T-6** | **某个大目录里有 197 篇** | **照直铺，不分段、不造假节点。** 折上时就一行；展开就是 197 行，约 10 屏——和今天翻目录页同一个量级、同一份滚动手感。做“按年月折段”只对一半的大目录有效（七个大目录里只有两个是日期名），做“按首字母折段”要引拼音表（不许引依赖）。 |

树的固定规则（**已定死，不要重开**）：

- 点一下文件夹 = **展开 + 选为当前文件夹，同时发生**。再点一下折上，但**选中保留**（高亮和落点都还在那个目录）。不拆成两个概念——手机上要第二下隐藏点击才选中，没人猜得到。
- 根目录那一行同样可选中；选中根即落点＝根。
- **缩进每层 14px，第 4 层封顶**；更深的层不再加缩进，行首用**层级记号**区分（记号长什么样归你）。本库最深 4 层，这条封顶是替开源后别人的深库定的。
- **44px 点击区靠行高保证**，不靠缩进。
- **名字放不下时左右滚动，不截断。** 代价记着：手机上横滑可能与竖滚抢手势；真机打架时退路是“行尾省略 + 选中后露出全名”，这属于实现阶段的事，设计时按“横滚”做，但**别把行尾塞满**，给退路留位置。
- **折叠状态跨会话记住**，单独存一份本机记录，**不跟着仓库版本号失效**（否则电脑上改一次仓库就全折了）。找不到的路径（改名、删除、换仓库）**静默丢弃**，不报错、不提示。
- **“打开的那篇”压过手动折叠**：打开一篇时它的祖先自动展开，折了下次出现也会自己开。代价明记：**当前这篇所在的那一支实际上折不上**——这是选“自动展开”换来的，不是缺陷。
- **不做“展开 / 收起全部”**：树每次出现会自动定位到正在读的那篇，“全部展开”等于把 197 行摊成十屏，正是这次要躲开的东西。

### 4.2 侧栏 · 搜索

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **S-1** | **有词，正在确认网络** | 搜索依赖“当前网络能问到版本身份”，那是一次很轻的请求（通常不到一秒）。这一态说“正在确认网络…”，**不许**直接说“没找到”。 |
| **S-2** | **断网，不给搜** | 明说“连不上服务端，搜索暂时用不了。恢复联网后再试。”**不许**用本机那份名单硬搜——它可能已经过期，搜出来的东西可能早被改名删掉了。 |
| **S-3** | **无结果** | 只有当“网络确认过 + 名单已到 + 确实没匹配”三者同时成立，才可以说“标题和路径里都没有”。 |
| **S-4** | **名单还在加载** | 与 S-3 分开说（今天说“文件名单还在加载…”）。**“还没问到”和“没有”是两件事**。 |

搜索的固定规则：

- 只搜**标题与路径**，不搜正文（全库正文搜索已定死不做的，别设计相关入口）。
- 只有**一组**结果，**按路径序**，不挂分组标题。
- 结果**就地替掉树**；点一条在**右边**打开，手机上侧栏随之收起。
- 有词时“新建”按钮收起来（它跟结果无关）。

### 4.3 侧栏 · 设置

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **P-1** | **设置面板（默认档：黑白 + 跟随系统 + 关于）** | 三块内容，见下。面板自带「‹ 返回目录」。 |
| **P-2** | **新建落点选了“指定目录”** | 选这一档才露出“是哪个目录”和它的选择入口。 |
| **P-3** | **指定的目录不见了** | 见 §5 的 F-6：不是在设置面板里报，而是在**打开新建弹窗的那一刻**当场报，并给两条出路。面板里要能直达“改通用路径”。 |

设置面板只装三块（**已定死**）：

1. **黑白模式**：三档 **黑 / 白 / 跟随系统**。本机没存过时**默认“跟随系统”**。**选完立刻生效，不设确认**——单选没有“未保存”的概念。当前选中哪一档要一眼看得出。**怎么摆、用什么控件归你。** 只影响这台设备。
2. **新建落点**：两档——(a) 落在**选中的文件夹**（默认档，没选中就落根）；(b) **总是落在某个指定目录**。它只决定**新建弹窗里预填哪个目录**；弹窗里照旧可以改这一次。
3. **关于**：版本号 + 构建那次的提交短号（形如 `0.1.0 · 3f9c2a1`）+ 项目地址一行小字。提交号取不到就只显示版本号。

**不装**：访问密码（那是服务端配置，前端只能记住和用、改不了）、连的是哪个仓库（前端今天拿不到，要显示得新开接口，而没人需要）。

**编辑态下侧栏锁死，所以设置天然不可达**，不需要额外规则。

### 4.4 侧栏 · 浮层（操作表、弹窗、目录选择器）

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **O-1** | **长按一行出来的操作表**（窄屏） | 重命名 / 移动 / 删除 + 取消。**文件夹行不响应长按**（它没有写操作）。长按有没有触点反馈、操作表长什么样，归你。 |
| **O-2** | **宽屏行尾悬停出现的「⋯」** | 只在悬停时出现，**不是常驻**。多大、离行尾多远，归你。 |
| **O-3** | **新建弹窗** | 只有两块：名字输入框 + 一个**已经填好的**目录。目录**就在弹窗里直接改**，不另设二级入口。 |
| **O-4** | **目录选择器**（新建与移动共用） | 逐层点进去、“就放这里”。这是今天“移动笔记”那套，**复用，不新造控件**（形态可以美化，交互不变）。 |
| **O-5** | **重命名弹窗 / 删除确认弹窗 / 移动弹窗** | 文案的字面已经定过（见附录 C），**照抄**。移动弹窗与新建弹窗是**同一个形态**（名字 + 已填好的目录）。 |
| **O-6** | **新建撞名** | 拒绝并说“这个名字已经有了”。**不自动加后缀、不弹二次确认、不把名字改掉**。点“取消”回到侧栏，什么都不发生。 |

树行的入口规则（**已定死**）：

- **树行不挂常驻「⋯」。** 46px 的按钮占 292px 侧栏的 16%，而且正落在拇指停靠的右下边缘，197 行滚过去误触率不低。
- **窄屏长按一行**出操作表；**宽屏行尾悬停**显示「⋯」。
- **正文顶栏永远有一个「⋯」，它是主入口**——长按没人猜得到，发现性得有人兜。
- **不做左滑**：已定“名字放不下时左右滚动”，左滑与横滑是同一个手势。
- **文件夹没有改名 / 移动 / 删除**（删一个目录 = N 个文件各写一次、每次核对版本，手机上误触一棵子树的代价最高）。
- 编辑态下「⋯」里三个动作**置灰但仍能按**，按了给一句“先保存或取消，再改文件”（按了毫无反应会被当成卡死）。

### 4.5 正文区 · 空状态与「最近打开」

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **E-1** | **空状态（第一次用，一条记录都没有）** | 没有“最近打开”可列，只剩那句提示。这一屏不能显得像出错了，也不能留一片空白让人以为没加载完。 |
| **E-2** | **空状态（本机有记录）** | 一句提示 + **最近打开的 5 条**。每条要能被认出来是哪一篇：**名字 + 一行浅色的父目录**（库里 905 篇有 **112 组同名**，只显示名字等于碰运气）。多小、放左右、什么颜色，归你。 |
| **E-3** | **其中几条已失效** | 空状态出现的那一刻，5 条**并行各问一次**（约一秒，一起来）。结果三档且**不许互相冒充**：在 → 正常；**不在了** → 标“已失效”，**条目不消失、留在原地**；**问不到**（断网/服务端报错）→ **不许标失效**，整批不标、不弹提示。核对期间**不显示“核对中”**：条目不闪、不灰、不挡，结果到了就地标上。 |
| **E-4** | **点了已失效的那条** | **重新问一次**（标注是上一次的结论，不是永久判决）。回来了就正常打开并撤掉标注；真不在 → 说“这篇不在了，可能被改名或删掉了”，并在提示条上给一个**“从列表里去掉”**的动作。**不自动删**——东西自己在眼皮底下消失，人会以为点错了或界面出毛病。 |

「最近打开」的固定规则：**只记路径**（不记内容指纹，所以搬走的笔记不追）；**记 5 条**，每次成功打开就置顶、去重、截断；**不按时间过期**；同一批路径**一分钟内不重复核对**（否则一天开关二十次空状态就是一百次请求）；本机会丢，但**界面上不交代**（换设备、清缓存就没了，写一句“只存在这台设备”只会让人以为有什么要保管）；**应用内删掉**正在读的那篇 → 那条去掉；**改名 / 移动** → 那条直接换成新路径。

### 4.6 正文区 · 阅读态

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **R-1** | **打开一篇，正文还在路上** | 有一小段加载。不能是空白页；也不要整屏骨架乱跳。 |
| **R-2** | **正文到了，但“全库名单”还没到** | 双链与图片此刻处于**“不知道”**那一态——不是“不存在”，也不是“坏了”。今天是个中性占位（图片显示“正在确认位置”）。**这个中性态要保留，并且和“确实找不到”在视觉上分得开。** 名单到了会整篇重画换掉它。 |
| **R-3** | **读失败：这篇不在了** | 明说“这篇不在了（可能被改名或删掉）”。与 R-4 分开。 |
| **R-4** | **读失败：连不上 / 要密码** | “连不上”说连不上；“要密码”直接弹解锁框，**不在它背后再喊一句没连上**。 |

阅读态的「编辑」入口在哪儿——**归你**（§7 第二栏）。但有两条不带位置的事实必须成立：

- 点「编辑」要先读一次远端最新版（约一秒），**忙态落在被按的那个按钮上**（“读取中…”），期间不能重复触发。
- 读到远端变过 → 换成最新再进编辑，并提示一句；**读不到就不进编辑**（停在阅读态，明说连不上，给“重试”）。理由：手机上不留正文副本，连不上时写下的字在保存那一刻必然丢。

### 4.7 正文区 · 编辑态

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **W-1** | **编辑中（键盘收起）** | 全屏输入区 + 「保存」「取消」。手机上**左上角那颗按钮是「退出编辑」**（回阅读态），不是“关掉这篇”——这样“返回”永远只退一层。侧栏锁死：宽屏下侧栏照旧在，但点别的笔记会被**拦住并说明原因**。 |
| **W-2** | **编辑中，键盘弹起** | **「保存」「取消」必须始终看得见、够得着。** 这是硬约束（§6 第 6 条）：布局跟随**可见视口**，不许假设“页面高度 = 屏幕高度”。放底部一条还是顶栏，归你。 |
| **W-3** | **有改动，要退出** | 按「返回」、按「取消」、按系统返回键，**都先问一句“放弃改动？”**（今天毫无拦截，返回 / 换一篇 / 浏览器后退都会让写下的字无声消失）。**这是新增行为。** |
| **W-4** | **保存中 / 保存失败** | 保存中有忙态，落在被按的按钮上。失败分两种且**不许混**：撞上远端改动 → 进冲突态（C-1）；其他（连不上、这篇不在了）→ 一句说得清的话，**不许说成“冲突”**。 |

编辑态的固定规则：退出按钮的忙态落在**被按的那个按钮**上，**不用全局提示代劳**；编辑态**不给「☰」把侧栏叫回来**（侧栏每多一个入口，就多一条“我的字去哪了”的路）。

### 4.8 正文区 · 冲突态

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **C-1** | **冲突合并（左右两栏逐字比对）** | **界面本身不改**：逐字比对、左右两栏、窄屏宽屏一致、点差异出气泡裁决。你只决定它在侧栏旁边怎么落位（手机上是全屏；冲突态同样锁死侧栏）。 |
| **C-2** | **冲突态底部那条动作区** | 今天只有“预览改动处理”一个按钮。**保留，里面的东西不改**，位置与形状归你。 |
| **C-3** | **预览层（sheet）** | 里面有“提交合并 / 收起预览 / 另存副本”，以及 keep-local / keep-remote 两种取舍。**不改。** 它从新骨架的哪儿升起，你定。 |
| **C-4** | **冲突态按返回** | **退回编辑态，草稿原样还在**。不退回阅读态、不回空状态、**不另加“远端改过”的提示**（用户刚从冲突界面出来，他知道）。冲突 → 编辑 → 阅读，每次退一层。 |

### 4.9 全局

| 编号 | 状态 | 必须交代的事 |
|---|---|---|
| **G-1** | **提示条：普通** | 一条，浮在界面里居中、离底 80px、2.5 秒自己消失。**形态与位置一个字不改**（高 32–36px、宽随文案、上限 80% 屏宽、13px 字）。它是**全局的、不属于任何一栏**，所以永远相对整个界面居中，**不跟着分栏走**。 |
| **G-2** | **提示条：带一个动作** | 同样形态，停 8 秒（删除后的“撤销”就是它）。 |
| **G-3** | **勾选：还没送到** | 点勾那一刻若没送出去，提示一次“还没送到，联网后自动再试”。**不留常驻记号、不做“正在保存”忙态**（这个状态平均存在时间很短，给它一个记号等于给树行长出状态位）。 |
| **G-4** | **勾选：真送不到了** | 点名那一篇 + 给一个**「打开」**（回到那篇看真实状态）。什么时候算“真送不到”：那一行被删了、那行的状态已经被人改过、那篇在别处被整篇改过、那篇不见了——补发再多次也没用。**不给“重试”按钮**（自动补发已取代它）。这条提示**不许被后续的“已保存”顶掉**——顶掉就等于这次失败静默了。 |
| **G-5** | **解锁框** | 服务端配了访问密码时出现。**只有一个任务：输密码。** 颜色已按存档生效（暗色用户不该每次打开先被一屏白刺一下），但框里**不给**切换主题的入口。 |
| **G-6** | **宽屏，侧栏收起** | 左上留「☰」，正文全宽。收起状态本机记住。 |

## 5. 交互时序

每条都写成“谁 → 按下 → 依次发生什么 → 失败怎么说”。**要按时序画，不要写形容词。**

**F-1 第一次打开应用（冷启动）**

0 秒：屏幕先按存档的颜色定好，**不许先白后黑闪一下**（见 §6 第 9 条）。同时向服务端要一次版本号。
0~1 秒：右侧空状态先出来（提示 + 5 条最近打开，5 条并行各问一次在不在）。左侧树进 T-1/T-2 的加载态。
若版本号没变：约 1 秒后树就绪（T-4）。
若版本号变了：**退回全量重拉，4.8~6.3 秒**——这期间树一直在加载态里，不许变成空树。
断网：树进 T-3（说“连不上”，给重试）；最近打开的 5 条**不许标失效**（问不到 ≠ 不在了）。

**F-2 手机上拉开 / 关上侧栏**

点左上「☰」→ 侧栏滑出，**同时**在历史里压一条占位（地址栏不变）→ 树按打开的那篇摆好（T-5）。
关闭三条路，**每一条都要把那条占位吃掉**：点侧栏自带的关闭键 / 点那 1/4 的薄遮罩 / 点开一篇笔记（自动收）。**不收走占位会造出一个假 bug**：手点关闭之后按返回，人觉得“按了没反应”。
侧栏开着时按系统返回 → **先收侧栏**，不动笔记。

**F-3 在树里换一篇**

点另一篇 → 手机上侧栏收起、占位吃掉 → 右侧换内容（不是换屏）→ 地址栏换成那篇 → 树里那行高亮、选中退回它所在的文件夹。
若当时**有改动没保存**：见 F-9（先问）。

**F-4 搜索**

在侧栏顶部输入框里打字（**中文走输入法组字**，见 §6 第 1 条）→ 有字的瞬间：树被结果替掉，**正文不动**。
先确认网络（S-1）→ 断网（S-2）/ 无结果（S-3）/ 名单未到（S-4），三种说法互不冒充。
点一条结果 → 右侧打开，手机上侧栏收起。

**F-5 进设置、回树**

点侧栏顶部“设置” → 面板就地替掉树（不进历史）→ 改黑白模式：**立即生效**，不确认。
点「‹ 返回目录」→ 回到树（**不是**按返回键回）。
此时按系统返回 → 收的是侧栏，不是“从设置退一层”。

**F-6 新建**

点侧栏“新建” → 弹窗（O-3）：名字输入框已聚焦，目录已按设置预填。
若设置是“指定目录”而那个目录**不在了** → 打开弹窗这一刻就用**一次轻请求**问过那一层，当场报“指定的目录不在了”，并给两条出路：去设置改 / 就在这里改这一次。**断网要说“连不上”，不许说“找不到”。**
输入名字 → 只填名字，不带后缀（自动补 `.md`）；回车等于确定。
撞名 → **拒绝并说“这个名字已经有了”**，不自动加后缀、不弹二次确认。
成功 → 弹窗关，**直接进那篇并进编辑态**，提示“已新建 X”。此时想改名得先退出编辑（空笔记“取消”的代价接近零，认了）。

**F-7 从阅读态进编辑**

点「编辑」→ 按钮进忙态“读取中…”（不许发第二次请求）→ 读回来：
- 版本号没变 → 直接进编辑，一个字不提示。
- 变了 → 换成最新再进，提示“远端已更新，已自动加载最新内容”。
- 读不到 → **不进编辑**，停在阅读态，说明连不上，给“重试”。

**F-8 编辑 → 保存**

打字（键盘可能弹起，保存/取消仍须可达）→ 点「保存」→ 忙态落在按钮上。
成功 → 回阅读态，提示“已保存”。
撞冲突 → 进冲突态（C-1），**草稿不能丢**。
其他失败 → 一句说得清的话（连不上 / 这篇不在了），**不许说成冲突**。

**F-9 有改动要退出编辑**

点左上「退出编辑」/ 点「取消」/ 按系统返回 → **先问“放弃改动？”** → 确认才退回阅读态，草稿丢弃；取消则留在编辑态，草稿原样。

**F-10 冲突里裁决与提交**

左右两栏点差异 → 气泡“采纳 / 不采纳” → 全部裁决完才能“提交合并”（还有差异时按钮不可提交）→ 提交成功回阅读态，提示“合并已保存”。
冲突态按返回 → **退回编辑态**（草稿在），不加提示。

**F-11 文件操作**

窄屏：长按一行 → 操作表（O-1）。宽屏：悬停行尾 → 「⋯」→ 同一张表。正文顶栏「⋯」→ 同一张表。
删除 → 确认弹窗（文案照抄）→ 删完：**右侧回空状态、侧栏不关、树里选中退回它所在的文件夹**，提示条带“撤销”停 8 秒。
重命名 / 移动 → 弹窗（O-5）→ 成功后：右侧打开新路径、树里选中它、地址栏跟着换。
**每写完一步，树要就地刷新**（今天写完树显示的是提交前的世界，要等切后台再回来再付一次 3~6 秒——这次不许）。

**F-12 勾选一个任务**

点勾 → 立刻记下“哪一篇、第几行、勾成什么”（**不存正文**）→ 提交：
- 成功 → “已保存”。写的不是屏幕上这篇时**点名哪一篇**。
- 失败但可补发 → “还没送到，联网后自动再试”（G-3），不留记号。
- 真的送不到了（那行被删、状态被人改过、那篇不见了）→ 点名 + 「打开」（G-4），**不被后续“已保存”顶掉**，不给重试。
换篇时这一笔**仍归原来那篇**（判据是“屏幕上的那篇变了”，不是“点了哪个按钮”）。

**F-13 从一条旧链接 / 分享链接进来**

分享链接（指向一篇）→ 落地就是那篇的**阅读态**，**侧栏关着**（别顺手拉开，那会让人以为打开的是个文件管理器）。
旧目录链接（指向一个目录）→ 那一级不在了 → **上退一级打开，并明说“这个目录不在了，已上退到这里”**。逐级往上试即可（最多四层），断网时说“连不上”而不是“找不到”。

**F-14 断网时的各处说话**

树 → T-3；搜索 → S-2；打开一篇 → R-4；保存 → 一句“连不上”；新建弹窗的目录核对 → “连不上”。
**同一个原因，四处都要说同一件事，且都不许说成“没有”。**

## 6. 硬约束

每条都给了理由。**没有理由的约束会被违反，而且违反的人不知道自己违反了。**

1. **不许换掉用户正在打字的那个输入框节点。**
   整页重画会把输入框换成新节点，**中文输入法的组字当场断掉**——实测：节点一换、组字再也不结束、接着敲的字母糊成一串（`ji` + `jih` → `jijih`）。这条**是布局决定的**，不是实现细节：搜索框、编辑区输入框所在的容器必须能在重画中存活。设计上的要求是——**别让“侧栏换内容”“结果刷新”“提示条出现”这三件事触碰输入框所在的区域**。
2. **点击区不小于 44px。**
   拇指。树行靠行高保证，不靠缩进。
3. **不引入 UI 框架、组件库、CSS 框架；图标自绘**（SVG），**不用图标字体、不用 emoji 当图标**。
   项目是无框架原生 JS；图标字体在弱网/离线是额外请求；emoji 跨平台长相不一致、无法对齐。
4. **正文的渲染结构不许动。**
   标题、双链、标签胶囊、勾选框、Tasks 记号、声明区、图片这套规则有既定实现与实测；你只决定**外面包多大、留多少白、最大行宽**。
5. **深浅两套都要有，且所有颜色必须是可切的值。**
   今天样式里有二十来处写死（白卡片、浅灰占位、双链下划线等）。视觉规范里每个颜色都要有一个**语义名**，并给出明暗两套取值与对比度。
6. **不许假设“页面高度 = 屏幕高度”。**
   键盘弹起后可见视口会小一截。凡是“贴在底部”的东西（保存/取消、弹窗、操作表）都要跟随**可见视口**，否则会被键盘盖住。
7. **失败不静默，也不互相冒充。**
   “找不到”“还没问到”“连不上”是三件事，界面必须分得开。这条在 §4/§5 里出现了十几次，是这一轮最常被违反的一条。
8. **地址栏只跟笔记走。** 侧栏开合、树展开、搜索词、设置面板，都不进历史。
9. **第一屏不许闪白。**
   主题读取与定色必须在**样式生效之前**完成，否则暗色用户每次打开先被白屏刺一下。这条是**实现顺序**问题，不是画法问题——但设计要在视觉规范里说清“页面底色由谁定”，别让第一帧落到默认白。
10. **撤销提示条的形态与位置不改。** 全局居中、离底 80px、高 32–36px、宽上限 80% 屏宽。它不属于任何一栏。
11. **冲突合并的逐字比对界面与预览层不改**，只落位。

## 7. 两栏：已定死 / 由你决定

### 第一栏：已定死（不要重开，重开也不接受）

- 一屏两栏；900px 断点；手机滑出占 3/4、留 1/4 露正文边缘 + 薄遮罩点关；宽屏常驻、可收起、记住。
- 开合**只靠按钮**，不做边缘滑动。
- 侧栏三块内容互斥（树 / 搜索结果 / 设置），换内容不进历史，面板自带「‹ 返回目录」。
- 点开一篇，手机上侧栏自动收起。

## 8. 交付物格式

两份文件，放在**这个目录下**（与这份任务书同级）。

### 8.1 `prototype.html` —— 能点的原型

- **一个单文件 HTML**，双击就能在浏览器打开，**零外部依赖**（不许引 CDN、字体、图标库；离线打开要完整）。
- **两套画布**：手机 **390×844**（主画布），宽屏 **1280×800**；另需能切换 **844×390**（手机横屏）和 **900px 上下各一档**验证断点。
- **§4 里每一个状态都要能单独看到**：原型自带一个“状态清单”入口（一个可折叠的浮层、或一个调试下拉），点一下直接跳到那个态。这一条是硬性要求——**不能只做一条主流程**，评审要能指着 T-3、E-2、G-4 说“这一屏”。
- **主流程要能真点通**：拉开侧栏 → 点开一篇 → 编辑 → 保存 → 撞冲突 → 裁决 → 提交；搜索 → 点结果；新建 → 改目录 → 撞名；长按 → 删除 → 撤销；设置 → 切暗色。
- **用假数据**，不要连真仓库。数据要像真的：905 篇量级、一个 197 篇的大目录、跨四层的路径、几个同名的日记。
- 附一个**模拟键盘**开关（把可见视口压到约 500px），用来验证 W-2。
- 附一个**尺寸标注**开关（显示出所有可点区域的边界），用来验证 44px。

### 8.2 `visual-spec.md` —— 视觉规范

精确到“另一个人照着能写 CSS”的程度。至少这些项：

| 项 | 要求 |
|---|---|
| **颜色** | 语义名 + 明暗两套值（十六进制）+ 用途一句话。至少覆盖：页面底、卡片/面、分隔线、主文字、次要文字、禁用、主色（可点/链接）、选中底、危险、提示条底、遮罩。给出**关键配对的对比度**。 |
| **字体** | 字号阶梯（含手机/宽屏两档用法）、字重、行高。正文行宽上限。 |
| **间距** | 一个有名字的刻度（4/8/12/16/24…），并说明树行内边距、正文内边距各取哪一档。 |
| **尺寸** | 44px 点击区；树行高；侧栏宽度（窄屏取 3/4、宽屏取多少）；图标尺寸与画布网格（如 24px 网格、1.5px 线宽）。 |
| **圆角与阴影** | 两三种，说明各自用在哪。 |
| **动效** | 侧栏滑出的时长与缓动、遮罩淡入、面板切换；列出哪些动效在“减少动态效果”下必须关掉。 |
| **图标清单** | 这次要画的每一个图标（☰、✕、新建、设置、搜索、返回、⋯、文件夹、笔记、已失效标记…），逐个给出：名字、用途、在哪出现。 |

## 9. 验收：怎么算合格

交付后按下面七条逐项过，**任何一条不过就不合格**。

1. **状态齐不齐。** 拿 §4 的表逐条点名：T-1…T-6、S-1…S-4、P-1…P-3、O-1…O-6、E-1…E-4、R-1…R-4、W-1…W-4、C-1…C-4、G-1…G-6，**共 41 个**，每一个都要在原型里点得到。缺一个就是漏了一屏。
2. **时序走得通。** 拿 §5 的 F-1…F-14 逐条走一遍，**每一步的“失败怎么说”都要能在原型里点出来**，并且“找不到 / 还没问到 / 连不上”在措辞与样态上分得开。
3. **输入法那条线没被踩。** 在原型里用**拼音输入法**往搜索框里连打一段中文（不要直接粘贴）：组字不断、不跳、不丢；侧栏换内容、结果刷新、提示条出现时也不断。
4. **键盘那条线成立。** 打开模拟键盘后，「保存」「取消」仍然完全可见、可点（不是被盖住、也不是只露一条边）。
5. **两套配色与两套画布。** 明暗都能切；手机与宽屏两套都成立；暗色启动时第一帧不白。
6. **没有外部依赖。** 断网打开 `prototype.html`，一切照常（图标在、字在、能点）。
7. **44px 量得出。** 打开尺寸标注层，所有可点区域都不小于 44×44；树在 292px 宽、四层缩进下，标题仍有约 130px 的可用宽度（约 8~9 个汉字）——**读得出是哪一篇**。
